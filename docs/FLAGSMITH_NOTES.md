  - `get_experiment_flag("result_view", identifier=...)` returns `Flag` with `value`, `variant`, `reason="SPLIT; weight=50.0"`, `experiment=ExperimentMetadata(id=1, name='result_view_experiment', in_experiment=True)`.
- V5. **Metrics & on-demand refresh (`as_of`)**:
  - Metrics support `Occurrence`, `Count`, `Sum`, `Mean`; `Occurrence` is used for `shipped_ambiguous` and `held_clear_win`.
  - Flagsmith v2.295.2 experiment wizard attaches **1 primary metric** per experiment (`shipped_ambiguous`, `expected_direction: decrease`). Secondary/guardrail metrics are not attached in the wizard (tracked separately as environment metrics / quiz SQLite cross-check — confirm in Phase 1/2 if `POST .../experiments/{id}/metrics/` supports attaching a second metric).
  - **Both** exposures and results are computed **on demand** via `flagsmith-task-processor`:
    - `POST /api/v1/environments/{env_key}/experiments/{id}/exposures/refresh/` -> `202 Accepted`
    - `POST /api/v1/environments/{env_key}/experiments/{id}/results/refresh/` -> `202 Accepted` (rate-limited to once per 5 minutes; returns `429` with retry seconds if called sooner).
    - Note: MCP exposes `get_experiment_exposures` and `get_experiment_results` (reads cached snapshot), **not** the `/refresh/` endpoints — so `McpClient` or `RestClient` should trigger REST refresh when stale (respecting 429 cooldown).
  - Confirmed raw `exposures` payload: `{"exposures": {"as_of": ..., "last_error_at": null, "refresh_requested_at": ..., "payload": {"timeseries": {"points": [{"bucket": ..., "new_identities": {"verdict": 1}}], "granularity": "hour"}, "excluded_identities": 0}, "is_final": false}}`.

## Confirmed G2 Tunnel & Security Notes (2026-11-25)
- **N8 (G2 Tunnel option — Cloudflare Quick Tunnels / `cloudflared`)**: Verified from `https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/` (updated Sep 30, 2026). Cost: **$0**, no Cloudflare account or domain required (`cloudflared tunnel --url http://127.0.0.1:3000`). Limits: up to **200 in-flight concurrent requests** (`429` beyond 200), **no uptime guarantee**, **no SSE** (quiz is plain SSR HTTP), and **ephemeral `*.trycloudflare.com` hostname** that changes on restart. Requires user approval before starting.
- **N8b (Named Cloudflare Tunnel domain requirement)**: Verified from `https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/get-started/create-remote-tunnel/` and `.../routing-to-tunnel/dns/` — publishing an app via a named Cloudflare Tunnel requires **a domain added to Cloudflare DNS** (*"Before you publish an application through your tunnel, you must add a website to Cloudflare"*; CNAME points `<subdomain>` to `<UUID>.cfargotunnel.com`). Without owning a domain, a named tunnel cannot serve a public hostname.
- **N8c (Quick Tunnel restart impact & stable redirect mitigation)**: Because browsers scope the `vid` cookie to the exact origin hostname, restarting `cloudflared` changes `*.trycloudflare.com` and **resets visitor identity** for returning users (causing re-bucketing on a new origin). To keep the public link stable if a restart ever occurs, share a **stable redirect URL** you control (e.g., a GitHub Pages static redirect page or an editable short-link redirect pointing to the active `trycloudflare.com` URL) rather than sharing the raw ephemeral URL directly — while still keeping `cloudflared` running uninterrupted during collection so visitor cookies remain bound to one origin.
- **Localhost-only bindings**: `docker/docker-compose.yml` binds `8000`, `8001`, `8002` to `127.0.0.1` only (verified via `netstat -ano`). Only quiz port `3000` will be exposed publicly.
